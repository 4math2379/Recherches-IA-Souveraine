IA souveraine sur Scaleway

Une API compatible OpenAI, servie par des modèles Mistral et hébergée chez Scaleway à Paris. Elle se déploie depuis GitHub avec Terraform. Une seule variable choisit où tourne le modèle : serverless, GPU Instance ou Managed Inference. Les applications ne changent pas.

Le code est écrit et validé hors ligne. Rien n'a été déployé.

Constat au 7 octobre 2026

Les instances L4, L40S, H100 et B300 sont en pénurie à fr-par-1, fr-par-2 et pl-waw-2. Seule l'ancienne RENDER-S est disponible. En Managed Inference, H100 est en rupture et L4 et L40S en stock inconnu.

Hors UE

RPG Map Gen dépend des États-Unis

Elle utilise les embeddings OpenAI, Amazon Nova Canvas via Bedrock pour les images, S3 à Francfort et MongoDB Atlas.

Architecture

Icônes officielles Scaleway (paquet @ultraviolet/icons, Apache 2.0). Les cadres en pointillés sont les backends GPU optionnels.

Serverless, au token GPU dédié, à l'heure Requêtes Sortie NAT, gestion Terraform

Les instances n'ont pas d'IP publique. La Public Gateway porte l'entrée HTTPS (redirection des ports 443 et 80), la sortie NAT et le bastion SSH. La passerelle IA expose l'alias mistral-chat, que les applications appellent toujours. Changer inference_mode le redirige vers un autre backend.

Déployer depuis GitHub

Une seule fois

Bootstrap

scripts/bootstrap.sh crée le bucket de state versionné et une application IAM pour GitHub Actions, puis affiche les secrets à enregistrer. Créez aussi l'environnement GitHub scaleway-prod et ajoutez-y des approbateurs.

Configuration

Éditer env/prod.tfvars

  • gateway_domain : votre domaine. Vide, la passerelle utilise <ip>.sslip.io.
  • allowed_api_cidrs : qui peut appeler l'API.
  • bastion_allowed_cidrs et ssh_public_keys : l'accès SSH.
Pull request

Plan automatique

Chaque PR qui touche scaleway/ lance fmt, validate et plan. Le plan apparaît dans le résumé du job.

Manuel, avec approbation

Apply

Actions › sovereign-ai / terraform › Run workflow › apply. Le job attend l'approbation de l'environnement scaleway-prod.

Applications

Brancher le SDK OpenAI

client = OpenAI(base_url="https://ia.example.fr/v1", api_key=MASTER_KEY)
client.chat.completions.create(model="mistral-chat", messages=[...])
client.embeddings.create(model="embeddings", input="forêt brumeuse")

Ce qui est vérifié, ce qui reste à faire

  • Vérifié :
    • terraform validate et fmt passent avec le provider scaleway 2.85.0, compilé depuis les sources.
    • Les templates cloud-init produisent un YAML valide.
    • Les noms de modèles, d'images, de types d'instances et de permissions IAM ont été relevés dans un compte Scaleway, en lecture seule.
  • Non vérifié :
    • Aucun plan ni apply n'a tourné.
    • Les appels à api.scaleway.ai sont bloqués depuis cet environnement.
    • Le certificat TLS de l'endpoint privé Managed Inference est à tester.
  • À durcir avant la production :
    • Fixer les versions des images.
    • Restreindre allowed_api_cidrs.
    • Garder le bucket de state privé : il contient la clé API.
