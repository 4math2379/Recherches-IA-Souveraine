Socle commun

Un seul module, quatre produits

Le réseau privé, la Public Gateway, la passerelle Caddy + LiteLLM et le choix d'inférence (serverless, GPU ou Managed Inference) sont partagés. Une correction du socle profite aux quatre produits.

Indépendants

Un state par produit

Chaque produit a son réseau, son state et ses secrets. Vous pouvez en installer un seul chez un client, ou les quatre dans un même projet.

Serverless d'abord

GPU en pénurie

Tous les GPU Scaleway sont en pénurie aujourd'hui. Les produits démarrent donc sur Generative APIs. Une variable suffit pour passer sur GPU dédié.

Sans IP publique

Tout passe par la passerelle

Les instances, les bases et l'entrepôt n'ont que des endpoints privés. Chaque application est publiée sur son sous-domaine, en TLS, derrière un filtre d'adresses.

Produit · products/rag

RAG : discuter avec ses documents

Les utilisateurs déposent leurs PDF et documents Word, puis posent leurs questions en français. Les réponses citent les passages sources. Documents, vecteurs, conversations et modèles restent à Paris.

ComposantService ScalewayRôle
ApplicationInstance PLAY2-MICRO (8 Go)Open WebUI : chat, ingestion, recherche, comptes et groupes
Vecteurs et donnéesManaged PostgreSQL 17, DB-DEV-M, privé, chiffrépgvector en halfvec avec index HNSW, conversations
DocumentsObject Storage fr-par, versionnéFichiers déposés, via une clé IAM limitée aux objets
ModèlesGenerative APIs via la passerellemistral-chat (Mistral Small 3.2) et embeddings (bge-multilingual-gemma2)

Après le premier apply

  1. Créer le compte administrateur sur l'URL de l'application, immédiatement : le premier compte créé devient administrateur.
  2. Créer une base de connaissances et y déposer les documents.
  3. Poser une question : dans une conversation, taper # pour choisir la base.

Choix et limites

  • Modèle d'embeddings : bge-multilingual-gemma2 produit 3 584 dimensions, ce qui tient dans l'index pgvector (4 000 maximum). qwen3-embedding-8b, avec 4 096 dimensions, ne tient pas.
  • Licence Open WebUI : le logo ne peut pas être retiré au-delà de 50 utilisateurs sans licence entreprise. À lire avant une revente en marque blanche.
  • Corpus sensible : passer en managed_inference sans repli serverless.
Produit · products/agents

Agents : workflows et outils

On construit des agents à la souris (outils, mémoire, appels d'API), on les teste, puis on appelle chaque flow comme une API. En option, les agents interrogent votre infrastructure Scaleway en lecture seule, via le serveur MCP officiel.

ComposantService ScalewayRôle
ApplicationInstance PLAY2-MICRO (8 Go)Langflow (licence MIT) : éditeur visuel, exécution, API REST et serveur MCP pour chaque flow
ÉtatManaged PostgreSQL 17, DB-DEV-M, privé, chiffréFlows, historique, variables globales
ModèlesGenerative APIs via la passerellemistral-chat (appel d'outils), mistral-medium (raisonnement), devstral (code), embeddings
Outil, en optionServeur MCP Scaleway, lecture seuleApplication IAM AllProductsReadOnly limitée au projet, clé invisible pour Langflow

Après le premier apply

  1. Se connecter en admin. Le mot de passe est dans Secret Manager (output admin_password_secret_id).
  2. Configurer le composant de modèle OpenAI avec les variables globales OPENAI_API_KEY et OPENAI_API_BASE, et le modèle mistral-chat.
  3. Brancher l'outil MCP Scaleway (option) : composant MCP Tools, URL http://scaleway-mcp:8090/mcp.
  4. Appeler un flow : /api/v1/run/<flow> avec une clé API Langflow.

Choix et limites

  • Pourquoi Langflow : sa licence MIT permet de le packager pour des clients. n8n, sous Sustainable Use License, le permet moins facilement.
  • Sortie internet : les agents sortent par le NAT. Ajoutez un proxy ou des règles sortantes pour une liste blanche.
  • À confirmer : la saisie d'un nom de modèle personnalisé dans le composant OpenAI, et le chemin /mcp du serveur Scaleway.
Produit · products/analytics

Analyse : interroger ses données en français

On dépose des fichiers CSV ou Parquet et on les charge dans un entrepôt ClickHouse managé. On pose ensuite ses questions à un assistant qui écrit et exécute le SQL, en lecture seule. Les tableaux de bord se font dans Superset.

ComposantService ScalewayRôle
EntrepôtData Warehouse for ClickHouse v26, 1 réplica, 2 à 4 vCPU, privéBase analytics. Administrateur scwadmin, utilisateur analyst en lecture
DépôtObject Storage fr-par, versionnéCSV et Parquet, chargés avec s3() grâce à une clé en lecture
Hôte BIInstance PLAY2-MICRO (16 Go conseillés en production)Superset 5.0 sur bi.<domaine>, chat analyste Open WebUI sur <domaine>, serveur MCP ClickHouse
MétadonnéesManaged PostgreSQL 17, DB-DEV-MSuperset et Open WebUI
ModèlesGenerative APIs via la passerellemistral-chat, mistral-medium (meilleur en SQL complexe), embeddings

Après le premier apply

  1. Récupérer le certificat de l'entrepôt : scw datawarehouse deployment get-certificate <id>. Le mettre dans clickhouse_ca_cert (secret CLICKHOUSE_CA_CERT en CI), puis relancer apply. L'hôte donne alors les droits à analyst et connecte Superset.
  2. Créer le compte administrateur du chat, immédiatement.
  3. Ajouter l'outil MCP dans Open WebUI : URL http://clickhouse-mcp:8000/mcp, jeton Bearer dans Secret Manager.
  4. Charger un fichier avec CREATE TABLE … AS SELECT * FROM s3(…), puis poser la question.

Choix et limites

  • Deux apply : le certificat de l'endpoint privé n'est connu qu'une fois l'entrepôt créé.
  • Superset managé : l'offre de Scaleway n'a pas encore de ressource Terraform. Superset est donc hébergé sur l'instance.
  • Lecture seule : garantie deux fois, par les droits SQL de l'utilisateur et par le serveur MCP (CLICKHOUSE_ALLOW_WRITE_ACCESS=false).
  • À confirmer : l'installation des pilotes dans l'image Superset 5.0 (uv pip) et la commande superset set-database-uri.

Déployer un produit

Une seule fois, pour tous les produits

Bootstrap

scripts/bootstrap.sh crée le bucket de state et l'identité GitHub Actions. Cette identité a désormais aussi les droits PostgreSQL, Data Warehouse et Private Networks. Créez l'environnement GitHub scaleway-prod avec des approbateurs.

Par produit

Éditer products/<produit>/env/prod.tfvars

L'objet platform regroupe le domaine, les plages autorisées, le mode d'inférence et l'accès SSH. Pour un domaine personnalisé, créez deux enregistrements DNS A vers public_ip : le domaine et *.domaine.

Pull request

Plan des quatre produits

Chaque PR lance fmt, puis validate et plan pour chaque produit en parallèle.

Manuel, avec approbation

Apply d'un produit

Actions › sovereign-ai / terraform › Run workflow : choisir le produit, puis apply. Chaque produit a son propre state, sovereign-ai/<produit>.tfstate (clé de state).
